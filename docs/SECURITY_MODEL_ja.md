## 信頼境界

AWHDLは、モデル、エージェント、MCPサーバー、決定的プログラム、クラウドサービス、人間をすべてデバイスとして扱います。これらのデバイスは信頼済みの制御プレーンを構成しません。解析、ポリシー評価、スケジューリング、予算強制、サンドボックス、完了検査、監査ログはAI Conductorの責務です。

## 意図する不変条件

1. 実効権限はシステム、ユーザー、プロジェクト、ワークフロー、デバイスの各ポリシーの共通部分であり、プロジェクト自身が権限を追加することはできません。
2. 明示的に信頼された機密解除器が区分を下げない限り、データの機密区分は単調に上昇します。
3. クラウド向け呼び出しは単一の外向き通信認可境界を通過します。
4. 静的な受理によって、実行時の外向き通信検査を省略することはできません。
5. 外部作用または破壊的作用には、ポリシーによる明示的な認可が必要です。
6. 自律ループは、デバイスの出力とは独立した上限を持ちます。
7. 通常の監査ログには、既定でrestricted以上のペイロードを記録しません。

## 機密区分の順序

ドラフト仕様全体では次を定義します。

```text
public < internal < confidential < restricted < secret
```

最初のセキュリティ検査マイルストーンでは、まず次を実装します。

```text
public < internal < restricted
```

Milestone 1は機密区分の表記をASTに記録するだけで、規則はまだ強制しません。

## セキュリティ問題の報告

公開報告には、秘密情報、非公開データセット、資格情報、restrictedのペイロードを含めないでください。再現に必要な最小のソースと、期待したポリシー判断および実際の判断を記述してください。
